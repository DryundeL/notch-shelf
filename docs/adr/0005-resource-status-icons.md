# ADR-0005: исходные ресурсы status icons без захвата экрана

Status: реализован общий поиск ресурсов без списка владельцев; замена screenshot-пути по прямому запросу пользователя.

Актуальное решение заменяет описанные ниже первоначальные адаптеры: для любого обнаруженного владельца проверяются типовые имена ресурсов и ограниченный поиск PNG/PDF/TIFF внутри Resources. Проверяются идентичность bundle, локальность и границы пути, размеры изображения; символьные ссылки пропускаются. Неоднозначные варианты не выбираются. Кэш ограничен и обновляется вместе с инвентарём. Обнаружение процессов больше не ограничивается первыми 128 владельцами; общий бюджет прохода 64 секунды, отдельного процесса — 800 мс. Неполный проход явно отмечается. 59 тестов прошли, включая неизвестного владельца, 200 процессов и раскрытие меню вниз через NSPopUpButtonCell. Ручная проверка новой сборки ещё требуется.

Ниже — история первоначальной реализации.

ScreenCaptureKit, получение снимков, настройки/запросы Screen Recording и кэш снимков удалены. Прежний `menuBarSnapshotsEnabled` — неизвестный ключ при декодировании v1 и не попадает в новое сохранение. Остальные настройки и hiddenBundleIDs совместимы.

`MenuBarResourceIconProvider` содержит явное соответствие владельца и проверенного ресурса. Для `ru.keepcoder.Telegram` это `StatusIcon`: найден в Assets.car установленного Telegram, успешно загружен через публичный Bundle.image(forResource:), 16×16 pt, непустая alpha-маска. Оригинальный executable не загружается (`bundle.isLoaded == false` в пробе). Ресурс читается на машине пользователя, не копируется в репозиторий или наше приложение. На чёрном контуре копия NSImage используется как template с белым tint. CFBundleIdentifier фактического owner bundle проверяется; URL должен быть локальным; размер ограничен 128×64 pt. Нет перебора произвольных картинок и fallback на Dock icon.

Это точный статический рисунок из ресурсов приложения, но не перемещение живого NSStatusItem. Счётчик, badge, смена состояния и выбор нескольких разных glyph одного владельца автоматически не определяются. После обновления владельца имя ресурса может измениться: тогда показывается подпись, не выдуманный заменитель. Другие bundle IDs, включая Qt Telegram Desktop, не объявляются поддержанными без проверки.

54 unit-теста прошли; ресурсная проба на реальном установленном Telegram успешна. Системное изображение текущего menu bar item через AX или приватный framework здесь не читается. Подписи для неподдерживаемых приложений остаются. Разрешение Accessibility нужно для обнаружения и действий меню; Screen Recording больше не используется. Существующее разрешение ОС пользователь может отозвать самостоятельно, TCC автоматически не изменяется.


Расширение: добавлены проверенные исходные ресурсы Vorssaint/MenuBarIcon, AWDLControl/MenuIcon, BetterDisplay/BetterDisplayStatus, Docker/statusItemIcon-0 и Cursor/app/molten/dist/tray/darwin/trayTemplate.png. Cursor использует точный вложенный путь через Bundle.url и NSImage(contentsOf:), остальные — Bundle.image(forResource:). Идентичность владельца проверяется до чтения; имена/пути не берутся из пользовательского ввода. Реальные установленные ресурсы загружены пробами, размеры от 16×16 до 29×22 pt. 56 unit-тестов прошли. Статические варианты не означают чтение текущего состояния владельца. VPN-ресурсы не угаданы и не заменены Dock images.

Исправление регрессии Cursor: одинаковые по содержимому копии tray-ресурса в разных каталогах не считаются неоднозначными. Разные изображения по-прежнему отклоняются. Кэш ресурсов сбрасывается при раскрытии шторки. Регрессионный тест сначала воспроизвёл ошибку; после исправления прошли 60 модульных тестов. Отдельная проба установленного Cursor загрузила ресурс 16×16 pt. Это не синхронизация живых статусов.
