# Требования и границы продукта

## Цель
Снизить визуальную перегруженность menu bar macOS, сохранив доступ к нативным меню сторонних приложений. На MacBook с notch — раскрывать шторку под вырезом, на внешних экранах — компактную floating shelf.

## Уточнение основной функции пользователем — 2026-11-01

Этот раздел имеет приоритет над прежним сужением MVP до собственной пустой панели и над экспериментами разделителей.

Основной сценарий:
1. Настройки показывают приложения, у которых обнаружены элементы системной строки меню; просто работающие приложения без обнаруженных menu bar элементов не выдаются за подходящие.
2. Пользователь выбирает приложения, чьи значки нужно убрать из строки меню. Выбор глобален, место раскрытия определяется дисплеем.
3. После успешного применения значки выбранных приложений отсутствуют в обычной строке меню и доступны в собственной шторке Notch Shelf. Это критерий результата, а не обещание физического переноса чужого NSStatusItem в наше окно.
4. Наведение на вырез камеры открывает шторку под ним. Перемещение указателя с выреза на значки или на открытое меню не закрывает шторку преждевременно. Escape и уход из активной области закрывают её с учётом состояния нативного меню.
5. Нажатия на значки открывают настоящее меню или действие приложения. Поддержку левого/правого клика, нескольких значков одного приложения и динамических значков проверяют явно. Копия значка без работающего действия не считается готовой функцией.
6. На внешнем мониторе отображается виртуальная область выреза; наведение открывает такую же шторку на этом мониторе. Один экземпляр панели следует за активным экраном.
7. Снятие выбора возвращает значок в строку меню. «Вернуть все значки» восстанавливает доступ независимо от текущего состояния шторки.

Hover и виртуальный вырез входят в основную функцию. Автозапуск, анимации и диагностика — обеспечивающие функции. Разделитель с раскрытием прямо в строке меню не заменяет этот сценарий.

Технический статус: обнаружение и AXPress проверены только для части приложений. Выборочное скрытие на macOS 27, получение актуального изображения значка и открытие нативного меню из шторки после скрытия не доказаны. Нельзя считать их реализованными или гарантировать универсальную поддержку. Для неподдерживаемого приложения переключатель недоступен с объяснением, значок остаётся доступным. При неудачном применении выбор не показывается как успешно применённый. Приоритет проверки: один реальный сторонний значок, затем список и групповые правила.

## Дополнение пользователя: два режима одновременно — 2026-11-01

Приложение должно поддерживать одновременно шторку у реального/виртуального выреза и сворачиваемую секцию оригинальных значков непосредственно в системной строке меню. Это уточнение отменяет прежнее исключение сворачиваемой секции из целевого продукта. Режимы не должны быть взаимоисключающим глобальным переключателем.

Подтверждённые ограничения:
- Раскрытие секции строки меню не должно само по себе возвращать в строку значки, назначенные шторке.
- Открытие/закрытие шторки не должно менять состояние сворачиваемой секции.
- «Вернуть все значки» снимает ограничения обоих механизмов. Сбой любого из них должен оставлять способ восстановить доступ ко всем значкам.
- Для шторки сохраняется запрет выбора приложения без доступного изображения. В секции строки меню используются оригинальные изображения и действия; условия допуска приложений в этот режим необходимо согласовать отдельно от доступности копии изображения.
- На внешних дисплеях сохраняется виртуальный вырез; правила приложений глобальны, геометрия интерфейса зависит от дисплея.
- Нельзя считать существующий PoC разделителя рабочим режимом: выборочное сворачивание и раскрытие оригинальных значков ещё требуется доказать на текущей macOS.

Подтверждено пользователем: обе группы работают одновременно. В шторку приложения назначаются только явным выбором через меню/настройки; сворачиваемая секция работает с оставшимися оригинальными значками в строке меню. Автоматического назначения новых приложений в шторку нет. Восстановление ранее сохранённого явного выбора при запуске сохраняется. Приложение не дублируется автоматически между двумя скрываемыми группами. Последняя фраза пользователя про «оставшееся в шторке» трактуется как «оставшееся в строке меню», что было явно сообщено в ответе.

## MVP / P0
- Запуск без Dock icon (`LSUIElement`), собственный управляющий status item.
- Пользовательский список скрываемых значков/групп в пределах подтверждённых возможностей ОС.
- Открытие шторки наведением на реальный или виртуальный вырез; закрытие по Escape/внешнему клику. Клик может служить дополнительным способом.
- Настройки reveal/hide, время задержки, анимации On/Off.
- Автозапуск по явному согласию пользователя.
- Поддержка подключений/отключений внешних дисплеев; окно всегда целиком на целевом дисплее.
- Безопасная кнопка «Показать всё / Восстановить доступ».
- Отсутствие постоянной активности CPU в idle.

## P1 после PoC
- Настраиваемая hover zone; drag-and-drop только при доказанном безопасном механизме.
- «Скрывать новые значки»: best effort discovery, явная allowlist/denylist, защита от повторного перемещения.
- Профили визуального режима для каждого дисплея; быстрый search.
- Опция separate/always-hidden sections.

## Non-goals
- Запись экрана/отслеживание рабочего стола, облачная синхронизация, сетевой backend.
- Гарантированный контроль всех системных значков на всех версиях macOS.
- Вмешательство в SIP, инжекция в чужие процессы, обход TCC.
- Системная модификация аппаратного выреза; виртуальная область на внешнем экране рисуется самим приложением.
- Собственное воспроизведение сложных меню вместо нативных.

## Acceptance criteria
- Тестовый набор status items виден в режиме recovery.
- После физического отключения монитора шторка перемещается на существующий экран.
- Нет доступа к данным Screen Recording, пока функция явно не активирована.
- Idle CPU в целевом сценарии медиана близка к нулю; p95 и wakeups измерены, а не угаданы.
- Неиспользуемые права не запрашиваются.
- Новые icon rules не переносят неизвестные items без подтверждённого способа отмены.

## Неясности / продуктовые решения
- Поддерживаемая macOS: предложено **macOS 14+** как baseline только после проверки SDK и PoC.
- Полное управление каждым отдельным item — **не гарантировано**; отображать UI capability.
- Mac App Store — не цель MVP, если для нужной функциональности потребуется private API.

## Уточнение поведения шторки и фактическая реализация — 2026-11-01

Выход из приложения отсутствует в шторке; он доступен в настройках/меню приложения. Требование пользователя: меню должно появляться возле выбранного значка в шторке, а изображение соответствовать status item. Прямой AXPress исходного значка из шторки и замена его app icon больше не считаются исполнением этого требования.

Текущий технический путь: локальное AppKit NSMenu строится из доступной AX-структуры выбранного элемента, стандартные пункты вызывают исходные AX-действия. Это представление структуры меню, не физический перенос оригинального NSMenu; нестандартные popover/custom views и ленивые меню без доступного AX-дерева не поддерживаются. Исходный значок не открывается автоматически ради получения дерева. Пустой/недоступный результат отображается как ограничение. Живые изображения status items получаются opt-in точечными снимками; они не обновляются непрерывно и не являются полноценным переносом UIElement.


## Языки интерфейса

Поддерживаются русский и английский: меню приложения и status item, настройки, сообщения об ошибках, диагностика и accessibility-подписи. По умолчанию язык определяется предпочтениями macOS для приложения. В настройках можно выбрать «Как в macOS», «Русский», «English»; изменение вступает в силу после перезапуска. Выбор хранится отдельно от правил скрытия и не меняет их. Имена приложений и пункты сторонних меню отображаются в языке, предоставленном владельцем. Неизвестные языки используют английский fallback. Переводы находятся в Resources/{ru,en}.lproj/Localizable.strings. Таблицы переводов и форматные аргументы покрыты тестами; визуальное размещение длинных текстов требует ручной проверки.


Текущая реализация режима строки: сохраняемый opt-in menuBarSectionEnabled и отдельная стрелка управляют оставшимися обнаруженными сторонними владельцами. Обе группы используют единственный системный allowlist; раскрытие строки не возвращает владельцев шторки. Системные элементы исключены из скрытия. После запуска режим раскрыт, широкий разделитель больше не используется. Сервис ОС подтвердил переключение ограничений на временных приложениях; визуальная работа реальных значков и нескольких мониторов ещё требует проверки.


## Приоритетное уточнение режима строки — Command-перенос

Предыдущая трактовка «все оставшиеся» отменена пользователем. Группу строки формирует только явный Command-drag оригинального значка влево от управляющего значка NotchShelf; перенос вправо исключает его. Наличие значка слева само по себе не назначает приложение группе. Старые настройки без menuBarSectionBundleIDs мигрируют в пустую группу, даже если режим включён. Новые приложения автоматически не выбираются. Назначение шторки остаётся только через меню/настройки.

В настройках — разрешение этой функции, без команды скрыть всех оставшихся. Основной значок NotchShelf: ЛКМ переключает непустую группу строки, ПКМ открывает существующее меню со списком шторки, настройками и выходом. Стрелка добавляется к основному значку только при наличии обнаруженных назначенных элементов; отдельного status item со стрелкой нет. При выключенной функции сохраняется обычное меню обоими кликами. Включение не скрывает ничего само по себе.

Состав строки хранится отдельно. Позиции читаются через AX только при Command-drag, без снимков и постоянного опроса. Подтверждённое изменение сохраняется и применяется после завершения перетаскивания. Неопределённая геометрия или неизвестный элемент не меняют группу. На текущем backend назначение относится к приложению-владельцу: несколько status items одного владельца скрываются вместе. Полный ручной Command-drag на установленной macOS и несколько дисплеев ещё требуют проверки.
