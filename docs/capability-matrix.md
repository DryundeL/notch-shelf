## Новый эксперимент: сворачиваемая нативная секция, 2026-11-01

По новому запросу пользователя решение Task 5 пересматривается только для эксперимента. Запуск с `--collapsible-section-poc` создаёт │ и стрелку. Command-перетаскиванием расположить тестовые значки левее │, стрелку правее │. Нажатие стрелки расширяет собственный разделитель до двух ширин экрана, повторное нажатие возвращает ширину 24 pt. Это эксперимент вытеснения, а не документированный API управления чужими значками. Совместимость и сохранение доступа после kill/hotplug пока не подтверждены. Автоматического сворачивания и сохранения collapsed-состояния нет. В настройках доступна команда «Вернуть все значки»; выход удаляет собственные разделители. Не проверять на критичных значках. AX и private API не используются. Предыдущее решение об отмене production conceal остаётся до ручной проверки.

Обновление управления: отдельная стрелка удалена. В режиме `--collapsible-section-poc` левый клик по NS переключает секцию, правый открывает настройки с «Вернуть все значки». Раскрытый разделитель занимает 12 pt; при сворачивании его подпись убирается. Порядок для эксперимента: сворачиваемые значки → │ → NS. Автоматическое перемещение чужих значков не выполняется. Предыдущие инструкции со стрелкой заменены этим управлением.

Результат ручной проверки пользователем: вариант с расширением до двух ширин экрана НЕ скрывает чужие значки, исчезает только разделитель. Это не рабочий conceal. macOS на машине — 27.0.1 (26A434).

Исправление эксперимента: ширина одного элемента ограничена `floor(min(screenWidths) / 2) - 64`, подпись разделителя сохраняется. Основание — наблюдения разработчика MenubarHide о том, что macOS 27 отбрасывает элементы шириной от половины дисплея: https://github.com/junior-rj/menubar-hide/blob/main/README.md#how-it-works . Это стороннее наблюдение, не гарантия Apple. Добавлены тесты политики ширины для нескольких экранов и некорректной топологии; unit-suite прошёл. Визуальное вытеснение в системный overflow после этой правки ещё не подтверждено. Одна ограниченная ширина может не обеспечить полное сворачивание на широком экране. Подмена скрытия исчезновением разделителя исключена: при расширении подпись больше не удаляется.

## Выборочное скрытие: первый вертикальный эксперимент, 2026-11-01

В установленном `/System/Library/PrivateFrameworks/MenuBarClientCore.framework` через Objective-C runtime непосредственно обнаружены классы `MBAssessmentModeConfiguration`, `MBAssessmentModeAssertion` и селекторы `initWithAllowedSystemItems:allowedBundleIdentifiers:`, `activateWithConfiguration:completionHandler:`, `invalidate`. Проба читала только метаданные, не активировала ограничение. Независимая реализация в `Infrastructure/NativeVisibility.{h,m}`; чужой исходный код не копировался. Публичное описание исследования: https://github.com/dwarvesf/hidden/pull/403 . Это private API, только эксперимент на macOS 27.0.1, не универсальный backend.

Сценарий: обычный запуск установленной `/Applications/NotchShelf.app` без старых PoC-флагов → настройки → сканирование (явный запрос AX при необходимости) → выбрать обнаруженный элемент → «Убрать выбранное приложение на 15 секунд» → открыть NS и нажать кнопку приложения в шторке. Выбор скрывает приложение целиком, включая несколько его значков. Первый этап показывает иконку приложения, а не копию изображения status item. AXPress уже существующего сканера вызывается по явному клику; его OK не доказывает открытие меню. Снятие ограничения через 15 секунд или «Вернуть все значки».

Инварианты: при старте ничего не скрывается; сохранённых правил пока нет. Менеджер и системные приложения не могут быть целью; остальные известные running bundle IDs включаются в allowlist. При изменении runningApplications ограничение снимается (неизвестные новые приложения не должны скрываться). При повторном сканировании, stop и ошибке ограничение снимается. Устаревшее завершение не применяется к следующему эксперименту. Timeout активации — 3 секунды. Параметры передаются как NSArray, системные слоты 0…63 сохраняются best effort; могут исчезнуть отдельные системные индикаторы, их поведение не подтверждено. Динамические Objective-C вызовы ограждены проверками селекторов и обработкой исключений. Завершение процесса должно снимать assertion согласно описанию механизма, но kill-recovery на этой машине пока не проверен.

Сборка и unit-suite прошли; добавлены проверки allowlist (исключается только выбранное приложение, менеджер сохраняется, системные/устаревшие цели отклоняются). Проверка через Computer Use заблокирована ошибкой `Sky Computer Use native pipe closed before response`. Реальное исчезновение значка, AXPress после скрытия, возврат после kill ещё не подтверждены. Hover и виртуальный вырез в этот проверочный шаг не входят и остаются обязательными следующими этапами основной функции.

Уточнение навигации: по просьбе пользователя оба клика по NS вновь переключают собственную шторку, включая запуск со старыми PoC-флагами. Настройки открываются шестерёнкой. Прежние инструкции о сворачивании секции левым кликом по NS и настройках по правому больше не действуют.

Непредоставленное меню не заменяется автоматическим открытием оригинала. Это локальное представление стандартной структуры, не оригинальное NSMenu и не поддержка custom popovers.

PNG только в памяти, общий лимит 4 MiB; Retina point-size сохраняется, app icons больше не используются. Без результата видна подпись и число успешно полученных изображений. Новая сборка прошла unit-suite. Тесты не выдают Screen Recording, не снимают реальные изображения и не доказывают совместимость меню сторонних приложений. Computer Use возвращает timeout для установленной NotchShelf. Эти сценарии остаются ручными проверками, не закрытыми критериями.

## Регрессии снимков и первого клика

Пользователь сообщил об исчезновении изображений и необходимости повторного клика в шторке. В коде исправлены: безусловная замена изображений пустым результатом повторного захвата и выдача новых UUID при каждом сканировании. UUID теперь сохраняется только для того же PID/bundleID и CFEqual AXUIElement; поиск ограничен элементами одного процесса. Кэш сохраняет прежний снимок того же live ID при неудачном обновлении, свежий снимок имеет приоритет. Чужой/исчезнувший ID не наследует картинку, лимиты памяти сохраняются, при отсутствии доступа к захвату кэш очищается.

Для клика добавлен acceptsFirstMouse, nonactivating panel становится key only if needed, кнопки не требуют предварительного key-фокуса. Активация запрашивается на первом клике; если приложение ещё не активно к моменту чтения AX-меню, запрос сохраняется до didBecomeActive с timeout 2 секунды. Закрытие панели отменяет отложенное меню. В настройках показываются агрегированные причины неудачного захвата без названий/координат или пиксельных данных.

Добавлены unit-проверки сохранения снимка при неудаче обновления, отказа наследования новым ID и приёма первого клика кнопкой. Это не замена ручной проверке первого клика и ScreenCaptureKit на установленной копии; GUI-канал по-прежнему возвращает timeout.

## Единый «вытекающий» контур

Отдельный бабл с зазором заменён по уточнению пользователя единым контуром. NSPanel остаётся техническим контейнером; видимую форму задаёт CAShapeLayer mask. ## Telegram без Screen Recording — ресурсный адаптер

По запросу пользователя screenshot-путь полностью удалён. В ресурсах установленного Telegram найден StatusIcon; проба Bundle.image(forResource:) загрузила 16×16 pt NSImage с непустой alpha-маской без загрузки executable. Подключён адаптер для ru.keepcoder.Telegram, без Dock fallback и без копирования чужих файлов в наш bundle. ScreenCaptureKit и системные запросы записи экрана отсутствуют в исходниках приложения. Сохраняются текущие настройки скрытия; устаревший capture-флаг игнорируется.

Badge и динамические состояния не переносятся; другие приложения пока имеют подписи. Подробнее ADR-0005. Единый вытекающий контур шторки из предыдущего этапа установлен и сохраняется.
