# План: Notch Shelf

Дата: 2026-10-24. Создан минимальный agent и каркас каталогов с пояснениями; остальное ниже — порядок реализации. Чеклист задач: [todo.md](todo.md).

## Обзор

Один agent-процесс без иконки в Dock. Свой `NSStatusItem` открывает одну ленивую `NSPanel`: под notch на встроенном экране, floating на внешнем. Настройки — `UserDefaults`. Скрытие чужих значков не пишется, пока PoC не покажет устойчивый и обратимый способ. Если не покажет, продукт остаётся шторкой плюс reveal нативной секции.

Спека уже есть в `docs/01`–`docs/13` и `docs/adr/`. План её не пересказывает.

## Решения, которые план не переоткрывает

- Swift 6 + AppKit, SwiftUI только для окна настроек. Ноль зависимостей. [adr/0001](../adr/0001-native-single-process.md), [02-tech-stack.md](../02-tech-stack.md).
- `MenuBarBackend` с typed capabilities. Public fallback всегда. Private adapter в этот план не входит. [adr/0002](../adr/0002-capability-backend.md).
- Правила items глобальные, режим панели — per display. Один `NSPanel`. [adr/0003](../adr/0003-global-items-per-display-ui.md).
- Первый запуск ничего не прячет. Reveal All существует до любой операции conceal.
- Разрешения Accessibility не запрашиваются, пока пользователь не включил функцию, которой они нужны. Screen Recording и Input Monitoring в MVP не запрашиваются.

## Скелет и кто его реализует

Папки и файлы-заготовки уже созданы по запросу пользователя. Наличие файла не означает выполнение задачи: кроме AppMain и StatusItemController исходники содержат только комментарии.

Зависимость снизу вверх. Горизонтально «сначала весь domain, потом весь UI» не делаем: первая рабочая вертикаль — клик по своему значку открывает и закрывает панель на правильном экране.

```
задача 1   AppMain, StatusItemController, Info.plist, xcodeproj, два test target
задача 6   Domain/ShelfState
задача 7   Domain/Geometry
задача 8   ShelfPanelController
задача 10  Ports/SettingsStore, UserDefaultsSettingsStore
задача 11  SettingsView (создаётся по пункту меню, не при старте)
задача 13  AppCoordinator, маркер восстановления
задача 14  DisplaySnapshot, DisplayProvider, ScreenDisplayProvider
задача 17+ Ports/MenuBarBackend и адаптер секций — только после go
```

Состояния панели: `closed → opening → open → closing → closed`. Смена экрана отменяет переход и пересчитывает anchor. Повторный клик идемпотентен. Очереди анимаций нет.

Потоки, которые скелет обязан выдержать, когда соответствующая задача закрыта:

1. Старт: прочитать настройки, проверить schema, поднять status item, не создавать панель.
2. Клик: экран источника → anchor → открыть. Никакого snapshot чужих иконок на этом пути.
3. Смена дисплеев: coalesce `didChangeScreenParametersNotification` → переякорить или закрыть. Окно целиком на живом экране либо закрыто.
4. Выход: снять observers. Процесс завершается. Маркер восстановления читается на следующем старте.

## Производительность

Сначала замер, потом правка. Пороги из [07-performance.md](../07-performance.md) — ориентир для обсуждения, не измеренный SLA.

| Режим | Порог | Когда снимать |
|---|---|---|
| Idle, панель закрыта | медиана CPU ~0%, p95 < 1% одного ядра | задача 4, повторить в 22 |
| Idle | `phys_footprint` 15–30 MiB, проверить, а не обещать | задача 4 |
| Idle | нет частого polling / wakeups | задача 4 |
| Панель с ~20 items | не больше +15 MiB к idle | задача 22, если items реально есть |
| 100 циклов open/close | нет монотонного роста retained memory | задача 22 |
| Hotplug | ориентир до 500 мс | задача 22 |
| Hover → visible | не мерить: hover не в этом плане | — |

Протокол: Release или Profile, без отладчика, 60 с стабилизации, затем 5 мин idle. RSS — вспомогательно, решение по `phys_footprint`. Activity Monitor только как перепроверка.

Ворота из спеки, без оптимизаций «на будущее»:

| Gate | Что сравниваем | Задача |
|---|---|---|
| 1 | пустой agent + свой status item | 4 |
| 2 | backend / AX, если фаза 4 вообще пошла | 22 |
| 3 | появление `NSPanel` | 9, строка в `docs/PERF.md` |
| 4 | snapshots иконок | нет в плане, пока нет фичи |
| 5 | несколько дисплеев | 22 |

Если число внутри шума прогона — правку откатываем. Нейтральное усложнение не оставляем. Попытки, включая откатанные, пишутся в `docs/PERF.md` (файл создаёт задача 4, не этот план).

В скелете заранее запрещено, потому что это антипаттерн бюджета, а не микрооптимизация: таймер 50/100 мс, display link и бесконечная анимация в idle, непрерывный трекинг курсора, `Task` без границы, полноэкранный `CGImage`, кэш без `costLimit`, AX-обход на пути отрисовки, пул соединений и HTTP-кэш (сети нет).

`Reduce Motion` и выключатель анимации — поведение продукта, не оптимизация. Их делаем в задаче 12 независимо от цифр.

## Открытые вопросы

- Bundle identifier: временный `local.notchshelf.app`, перед распространением нужен собственный reverse-DNS.
- Deployment target в каркасе: macOS 14.0; запуск на macOS 14 ещё не проверен. На машине разработки уже стоят macOS 27.0.1 (26A434), Xcode 27.0, Swift 6.4, SDK 27.0, arm64. Гипотеза спеки «macOS 14+» этой проверкой не подтверждена и не опровергнута: её закрывает сборка с выбранным deployment target в задаче 1.
- App Sandbox: не включать и не выключать молча. Решение в задаче 24, вместе с entitlements. До этого файл entitlements не добавляется.
- Подтверждение человека на задаче 5, прежде чем писать conceal.

## Приоритетное уточнение 2026-11-01: шторка выбранных приложений

Пользователь уточнил основной результат: настройки со списком menu bar приложений → выбор скрываемых → исчезновение выбранных значков из строки → рабочие значки в шторке по hover на notch, виртуальный notch на внешнем дисплее. Это отменяет сужение продукта до пустой собственной панели; прежняя отмена задач 17–20 больше не определяет целевой объём, но не означает, что их механизмы проверены. Детальный сценарий: `01-product-requirements.md`.

Зависимости возможностей и порядок:
1. Доказать для одного реального стороннего приложения обратимое выборочное скрытие на текущем OS build; аварийное восстановление обязательно. Эксперимент широкого разделителя этого не доказывает.
2. Для того же приложения доказать отображение актуального значка и вызов настоящего меню из панели после скрытия. Запрашивать разрешения только при включении соответствующей функции. Если требуется захват, сначала доказать его доступность на macOS 27, не обещать рабочие snapshots по старым моделям окон.
3. Объединить эти операции в один проверяемый сценарий; после успеха подключить список из диагностики и сохраняемые правила выбора. Bundle ID не подменяет идентичность нескольких элементов одного приложения; неизвестный/исчезнувший элемент не скрывать.
4. Добавить событийный hover реального выреза и удержание панели при переходе к нативному меню, без частого polling.
5. Добавить виртуальный вырез на внешнем мониторе, переключение единственной панели, hotplug и sleep/wake.
6. Пройти recovery после kill, отказа прав, перезапуска приложения-владельца, изменения значка, нескольких дисплеев и измерить бюджет.

Критерий готовности — целевой пользовательский сценарий, а не число реализованных вспомогательных экранов. Текущий прототип разделителей остаётся диагностическим и не считается исполнением пунктов 1–3.


## Выполнение пункта 5: сон и пробуждение, 2026-11-01

Перед сном панель закрывается без анимации, hover-зоны убираются. Изменение дисплеев и запоздалые события наведения не включают их до пробуждения. После пробуждения конфигурация экранов перечитывается; повторное уведомление wake без предшествующего sleep не запускает новый проход. Наблюдатели снимаются при stop. Сценарии уведомлений покрыты тестами на изолированном NotificationCenter и fake DisplayProvider. Живые sleep/wake, отключение внешнего монитора, recovery после kill и замеры бюджета остаются открытыми; программный сон пользовательского Mac для теста не запускался.


## Пункт 6: восстановление при потере доступа, 2026-11-01

Проверка Accessibility объединена для применения выбора и открытия меню. Отказ возвращает значки, отменяет поколение текущей операции, очищает устаревший инвентарь и приостанавливает автоприменение до явного успешного выбора. Проверяется также незавершённое скрытие. После ответа сервиса повторно проверяются разрешение и состав процессов; устаревший результат не сохраняется. Отказ сервиса и ошибка сохранения приостанавливают автоматические повторы. Тесты используют подменяемую проверку доступа, не меняют TCC и не скрывают реальные приложения. Recovery-маркер проверен в изолированном UserDefaults. Реальные отзыв прав во время скрытия, отказ приватного сервиса, kill -9 и восстановление после перезапуска ещё требуют ручного прогона.


## Новая вводная: совместные режимы строки меню и шторки

Пользователь добавил одновременную работу двух режимов. Прежние исключения секции строки меню из продукта не действуют; эксперимент разделителя не считается её готовой реализацией.

Порядок доработки:
1. Распределение уточнено: в шторку — только явным выбором через меню/настройки; секция строки — оставшиеся оригинальные значки. Обе группы работают одновременно. Существующий hiddenBundleIDs сохраняет смысл назначений шторки; автоматического переноса новых приложений нет.
2. Проверить обратимое сворачивание оригинальных значков отдельно от шторки. Выявить ограничения расстановки значков; не обещать автоматическую сортировку, пока механизм не подтверждён.
3. Добавить правила размещения с обратимой миграцией текущего hiddenBundleIDs в назначение шторки. Сохранённый выбор не должен молча попадать в новый режим.
4. Развести состояние раскрытия секции и панели. Скрытие шторки не должно исключать владельцев секции из системной строки; раскрытие секции не должно отменять скрытие владельцев шторки.
5. Объединить Reveal All, остановку и recovery для обоих механизмов. Проверить частичный отказ, незавершённые операции и перезапуски владельцев.
6. Проверить встроенный/внешний экран и сочетания двух режимов. Нагрузочный прогон 100 раскрытий должен учитывать каждый режим отдельно и их совместную работу; предыдущий baseline остаётся измерением закрытого состояния без выбранных приложений.

Это изменение требований и плана, а не готовая функция установленной сборки.


## Локализация ru/en — реализовано

Добавлены стандартные .lproj/Localizable.strings для русского и английского. Единый выбор языка используется Swift/AppKit, SwiftUI и ObjC-сообщениями сервиса скрытия. Выбор «система / ru / en» хранится отдельно в shelf.language и применяется со следующего запуска. Таблицы подключены к resources target; тесты проверяют полноту ключей, форматные аргументы и безопасную подстановку стороннего текста. Меню сторонних приложений не переводятся. Эта работа не реализует сворачиваемую секцию строки: её проверка и реализация остаются следующей функциональной задачей.


## Режим строки — реализация 2026-11-01

Обе группы объединены в один системный allowlist: назначенные шторке владельцы исключаются всегда, оставшиеся обнаруженные сторонние владельцы — только при свёрнутой строке. Раскрытие строки сохраняет скрытие шторки. NS-меню не меняет назначение, отдельный status item со стрелкой управляет строкой. Включение — отдельная сохраняемая настройка menuBarSectionEnabled; старая схема декодируется с false. Состояние раскрытия не сохраняется между запусками, после старта строка раскрыта. Обычное обновление инвентаря сохраняет намерение свернуть строку; ошибка/потеря прав/Reveal All отменяют его. Системные и собственные значки не скрываются. Исходное изображение для режима строки не требуется, поскольку возвращаются оригинальные элементы, а не их копии.

Старый механизм широкого разделителя и его расчёт ширины удалены. Перестановка системных значков, запись системных preferences и захват экрана не используются. Новый режим ограничен тем же проверенным OS build и доступностью private API, что шторка.

Проверки: тесты совместного скрытия, независимого раскрытия, сохранения состояния при сканировании, режима без шторки/изображений, общего возврата, устаревшего callback, отказа и миграции. Системный сервис подтвердил две операции на отдельных временных приложениях (обе группы → только шторка); ограничение снималось после прогона. CGWindowList не подтверждает видимость новых status items: AppKit сообщил proxy window number 4294967296, не сопоставимый с onscreen windows. Поэтому визуальный результат не объявляется проверенным. Инструмент управления установленным приложением вернул timeoutReached. Ручной прогон на реальных значках остаётся открытым.


## Коррекция режима строки по уточнению пользователя

Автоматический набор всех остальных владельцев удалён. Добавлен сохраняемый menuBarSectionBundleIDs (по умолчанию пустой) и изменение состава только после Command-drag конкретного обнаруженного значка относительно NotchShelf. AX-геометрия сопоставляется до/после, координаты переводятся из AX в AppKit; обычный клик, неизвестный источник и сброс вне строки не меняют назначения. Два mouse-event monitor устанавливаются только при включённой функции и снимаются при выключении/stop; клавиши и движения курсора непрерывно не записываются. После mouse-up выполняется единственный отложенный проход геометрии для завершения удалённой раскладки.

Отдельная стрелка удалена. При включённом режиме кнопка NotchShelf различает ЛКМ/ПКМ; текущий контекстный menu строится на ПКМ. Стрелка рисуется в том же значке только для непустой обнаруженной группы. При выключенном режиме сохраняется штатное меню обоими кликами. Ручной GUI-прогон остаётся открытым; тесты геометрии и состава группы его не заменяют.
