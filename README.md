# Notch Shelf

Нативное приложение для menu bar macOS на Swift 6 и AppKit. Выбранные приложения убираются из строки меню и доступны через собственную шторку.

## Текущая версия: выбор приложений и наведение

Запуск установленной копии: `open /Applications/NotchShelf.app`. Клик по NS сразу открывает штатное контекстное меню со списком приложений в шторке, «Настройки…» и «Выйти из Notch Shelf». Шторка раскрывается наведением и содержит только кнопки приложений. В секции «Приложения в шторке» отметьте приложения и нажмите «Применить выбор». Выбор сохраняется; 15-секундное ограничение первого прототипа снято. «Вернуть все значки» снимает ограничение и очищает сохранённый выбор.

При активном скрытии наведите курсор на область выреза камеры или полосу 16 pt под ним. На экране без выреза вверху по центру появляется виртуальная чёрная область: наведение раскрывает ту же единственную шторку на этом экране. Удержание шторки проверяется по видимому контуру, а не прозрачным углам окна. При уходе курсора шторка сразу начинает сворачиваться; переход к кнопкам отменяет закрытие. Открытое меню приложения удерживает шторку. Левый и правый клики по кнопке открывают локальное AppKit-меню возле неё, построенное из доступной AX-структуры приложения. Выбор пункта вызывает его исходное действие; оригинальный значок для показа меню не нажимается. Слайдеры, нестандартные popover и меню без доступного AX-дерева не поддерживаются — показывается ограничение. Это представление меню, не физический перенос чужого NSMenu.

Кнопка выхода из шторки убрана; выйти можно через настройки или меню NS. Захват экрана полностью удалён. Значки ищутся автоматически в ресурсах каждого обнаруженного приложения: по стандартным именам status/menu/tray и ограниченному поиску файлов. Списка разрешённых bundle IDs нет. При неоднозначном или отсутствующем ресурсе выбор для скрытия отключён; приложение остаётся в системной строке. Доступность проверяется при обновлении списка и перед ручным или автоматическим скрытием. Иконка Dock не используется. Это статические ресурсы: живые badge и состояния автоматически не воспроизводятся. Разрешение Screen Recording не требуется. Меню раскрывается под кнопкой средствами AppKit; при нехватке места система может изменить направление.

Скрытие остаётся экспериментальным private API для macOS 27.0.1. На старте без сохранённого выбора сканирования и запросов прав нет. С сохранённым выбором выполняется ограниченный AX-проход без запроса новых прав; при успешном обнаружении правила применяются повторно. Изменение списка процессов снимает ограничение и запускает обновление по событию; неизвестные элементы не скрываются по сохранённому правилу без обнаружения. При ошибке сохранения значки возвращаются. Маркер незавершённого сеанса приостанавливает автоприменение после сбоя до явного «Применить выбор»; marker на UserDefaults — best effort, не транзакционная гарантия при потере питания.

Проверка: unit-тесты прошли, включая миграцию старой схемы без hiddenBundleIDs, ограничения списка, выбор нескольких приложений, восстановление и геометрию hover-зон. Пользователь подтвердил скрытие и открытие нативного меню в первом прототипе. Hover, новый множественный выбор, hotplug и kill-recovery требуют ручной проверки новой сборки. Замеры производительности не выполнены.


## Язык

Интерфейс поддерживает русский и английский. В настройках → «Общие» → «Язык приложения» доступны язык macOS, Русский и English. После смены языка перезапустите приложение. Меню сторонних приложений сохраняют исходный язык владельца. Правила скрытия от выбора языка не меняются.

Подтверждён следующий функциональный этап: шторка и сворачиваемая строка работают одновременно; в шторку приложения попадают только через явный выбор в меню/настройках, а секция строки управляет оставшимися оригинальными значками. Режим строки включается в настройках → «Режим строки меню» → «Разрешить скрытие через Command-перетаскивание». Удерживая Command, перенесите оригинальный значок влево от NotchShelf для добавления в скрываемую группу; перенос вправо исключает его. Включение функции само по себе ничего не скрывает. ЛКМ по NotchShelf раскрывает/сворачивает непустую группу; ПКМ открывает существующее меню. Стрелка появляется рядом с основным значком только для непустой обнаруженной группы. Отдельной стрелки нет. Шторка по-прежнему заполняется только через настройки. Backend скрывает всех status items выбранного приложения-владельца вместе. Работа нового жеста на реальном экране ещё требует ручной проверки; скрытие ограничено доступностью private API macOS 27.0.1.

## Сборка и запуск

Открыть `NotchShelf.xcodeproj`, выбрать схему `NotchShelf` и запустить через Run.
Приложение появляется в menu bar как `NS`, без окна и значка Dock. Выход — из меню значка.

Локальная сборка без Developer ID:

```bash
xcodebuild -project NotchShelf.xcodeproj -scheme NotchShelf \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath build/DerivedData CODE_SIGNING_ALLOWED=NO build
```

Для проверки сборки приложения и обоих тестовых таргетов заменить `build` на `build-for-testing`.
Unit-тесты добавлены. Результат сборки: `build/DerivedData/Build/Products/Debug/NotchShelf.app`.

Среда разработки: Xcode 27.0 (27A266a), Swift 6.4, SDK macOS 27.0, arm64.
Выбраны Swift language mode 6 и deployment target macOS 14.0; запуск на macOS 14 ещё требует проверки.
Доступны Debug, Profile и Release. Bundle identifier `local.notchshelf.app` временный.
Подпись и notarization описаны в [плане выпуска](docs/12-build-release.md).

## Диагностика значков menu bar

Меню **NS → Сканировать значки…** запускает один автоматический AX-проход по работающим приложениям. При отсутствии Accessibility приложение сначала объясняет назначение доступа и предлагает запросить его. После выдачи доступа в системных настройках повторите команду. На обычном запуске разрешения не запрашиваются и сканирование не выполняется.

Отчёт показывает bundle ID приложения, число доступных элементов, роли, наличие identifier, доступные действия и числовые AXError. Пустой результат или ошибка не означают отсутствие значка: приложение может не поддерживать AX или завершиться во время прохода. Наличие `AXPress` не доказывает открытие меню — сканер действий не выполняет.

Ограничения: 128 процессов, 32 элемента на процесс, бюджет около 8 секунд плюс завершение текущих AX-вызовов с timeout 0,2 секунды. Одновременно выполняется один проход. Результат хранится только в памяти до завершения приложения; его можно выделить и скопировать вручную. Текст меню, заголовки окон, снимки и значения идентификаторов не собираются. Постоянного наблюдения и polling нет.

Сборка без стабильной подписи может потребовать повторной выдачи Accessibility после пересборки. Разрешение выдаёт пользователь, приложение его не обходит.

В окне диагностики кнопка **Скопировать отчёт** помещает исходную строку целиком в системный буфер обмена (заменяя его содержимое). Для фоновых процессов без ExtrasMenuBar показываются только суммарные числа по AX-статусам. Это сокращает вывод и не раскрывает названия helper-процессов.

### Проверка открытия

После сканирования выберите приложение и элемент в списке, нажмите **Проверить открытие**. Только AXMenuBarItem с AXPress попадают в список. Кнопка выполняет одно действие выбранного значка: оно может открыть меню либо выполнить другое поведение, заданное владельцем значка. Автоматического перебора нет.

Окно диагностики скроется, чтобы не мешать чужому меню. После визуальной проверки закройте меню через Escape и верните отчёт через **NS → Показать отчёт**. Результат AXPress добавляется к копируемому и сохраняемому отчёту; OK означает принятие AX-операции, а не доказанный показ меню. Повторный запуск стороннего приложения требует нового сканирования. Номера #0/#1 диагностические, не постоянные идентификаторы.

## Собственная панель

Левый клик по **NS** открывает/закрывает одну лениво создаваемую панель. Правый клик открывает меню диагностики и выхода. Escape и клик снаружи закрывают панель. Она размещается под notch на экране с соответствующими safe-area признаками, иначе под значком; рамка ограничена visibleFrame. Смена дисплеев или Space закрывает панель. Панель пока содержит информационный текст, без копий чужих иконок и без анимации.

Проверка 2026-10-31: 8 unit-тестов прошли (автомат, геометрия, отчёт, отказ для неизвестного AX-элемента). Автоматическая ручная проверка через GUI недоступна: Computer Use timeout. Пользователь подтвердил работу панели, включая базовые сценарии открытия/закрытия. Настоящий notch, внешний монитор и Spaces отдельно не проверены. Этот результат не закрывает performance Gate 3.

## Обновлённая навигация

По запросу пользователя оба клика по NS (левый и правый) переключают одну компактную панель. Отдельного контекстного меню больше нет. Шестерёнка внизу панели открывает отдельное окно «Notch Shelf — Настройки» с командами сканирования, показа отчёта и выхода. Окно настроек создаётся лениво и повторно используется. Старые инструкции про меню правого клика заменены этой навигацией. После проверки AXPress отчёт возвращается через шестерёнку → «Показать отчёт».

Окно настроек использует SwiftUI: положение панели сохраняется и применяется при следующем открытии. Предпочтения анимации сохраняются, её выполнение добавляется в Task 12. Автозапуск подключён через SMAppService.mainApp (Task 21). Ошибка сохранения показывается в окне без изменения значения; чужая версия схемы не перезаписывается.

Анимация появления панели подключена к настройкам: fade-in с выбранной длительностью, мгновенный показ при выключенном тумблере или системном Reduce Motion. Закрытие мгновенное. Устаревшее завершение анимации не меняет состояние после закрытия.

В настройках секция «Дисплеи» задаёт режим отдельно для подключённого экрана. Ключ — best-effort UUID, не название и не runtime ID. Дубликат/отсутствие UUID дают floating без общего профиля. Старые настройки без perDisplayModes читаются с сохранением прежних значений. Минимальный режим вместо панели открывает настройки; sleep/wake закрывают панель.

## Автозапуск

Шестерёнка → «Запускать при входе» регистрирует или снимает регистрацию приложения через `SMAppService.mainApp`. При первом запуске регистрация не выполняется. Тумблер показывает системный статус, а не сохранённое предпочтение; статус обновляется при открытии настроек и возвращении приложения в активное состояние. Если требуется разрешение, окно показывает пояснение и кнопку перехода в «Объекты входа». Ошибки показываются без автоматических повторов. Сохранённый флаг не используется для повторной регистрации при запуске.

Проверка 2026-11-01: сборка и suite NotchShelfTests прошли, включая три теста автозапуска с подменой системной службы. Реальная регистрация, снятие регистрации и вход в сессию требуют ручной проверки; тесты не меняют системный автозапуск.

Исправление 2026-11-01: статус `.notFound` больше не блокирует явную попытку регистрации. В системном журнале он сопровождался `record not found` до регистрации; это не доказательство непригодности сборки. Ошибка операции показывает домен и код NSError. Подписанная локальная сборка: `build/LocalSigned/Build/Products/Debug/NotchShelf.app`. Unit-suite прошёл после исправления; фактическая регистрация ещё требует проверки.

## История: первая проверка выборочного скрытия на macOS 27.0.1

В настройках добавлен эксперимент одного приложения. Нужна установленная копия `/Applications/NotchShelf.app`, обычный запуск без флагов разделителей. Выполните сканирование, выберите обнаруженный значок и нажмите «Убрать выбранное приложение на 15 секунд». Скрытие использует private API и может влиять на системные индикаторы; ограничение временное и снимается также кнопкой «Вернуть все значки». В панели NS появляется кнопка с иконкой приложения для проверки AXPress после скрытия. Это ещё не готовая hover-шторка и не точная копия status icon; фактический результат требует ручного подтверждения. Подробности и ограничения — в `docs/capability-matrix.md`.

Список значков в настройках загружается автоматически при их открытии, если Accessibility уже разрешён. При отсутствии доступа рядом с выбором приложения показывается кнопка выдачи разрешения; после возвращения из системных настроек список обновляется. «Обновить список приложений» запускает тот же ограниченный AX-проход без открытия отчёта поверх настроек. Пустой результат, отсутствие доступа и выполняющееся сканирование отображаются раздельно. Диагностический отчёт остаётся доступен отдельной командой.

Открытие настроек переводит приложение в обычный режим macOS: собственный значок в Dock, участие в Cmd+Tab и меню приложения. Клик в Dock возвращает окно настроек и разворачивает его после минимизации. При закрытии настроек запрашивается возврат в accessory-режим; фоновая шторка продолжает работать. При обычном старте окно настроек и Dock не показываются. Перезапуск установленной копии необходим после обновления. Сборка и существующие unit-тесты прошли; отображение Dock на текущей macOS требует ручной проверки.


Обновление меню и изображений: сборка и unit-suite прошли, включая ограничения crop-геометрии, отключённое по умолчанию согласие на захват, отказ для неизвестных menu tokens и отображение состояний локального меню. Реальные изображения status items, доступность скрытых AX-меню и выполнение их действий требуют ручной проверки установленной новой сборки; прежнее подтверждение пользователя относится к старому AXPress-пути.


Последнее уточнение навигации: NS в строке меню открывает обычное NSMenu сразу, без AX-сканирования на пути клика. Приложения перечислены информационными строками; команды — настройки и выход. В hover-шторке нет шестерёнки и выхода. Старые инструкции о переключении панели обоими кликами NS и шестерёнке больше не действуют. Unit-suite: 45 тестов прошли, включая состав меню NS; визуальное поведение требует проверки установленной копии.

Исправление регрессий: неудачный повторный захват больше не заменяет имеющиеся снимки пустым набором. Идентичность сохраняется при совпадении PID, bundle ID и AX-объекта; новые элементы не наследуют старое изображение. Для первого клика в hover-панели добавлены click-through и ожидание didBecomeActive перед popup, с отменой при закрытии и timeout. В настройках видны причины отказа получения изображений. 47 unit-тестов прошли; первый клик в реальном UI и захват требуют проверки установленной новой сборки.

Новая форма шторки: borderless чёрная область без заголовка, светлой подложки и стандартного оформления окна. Начальная геометрия на MacBook берётся из фактического выреза (auxiliary areas + safe-area top); область расширяется вниз с сохранением верхнего края. Закрытие сворачивает её обратно. На внешнем дисплее виртуальная область 180×24 pt; раскрытая ширина от 420 pt и ограничена экраном. Reduce Motion и выключенная анимация дают мгновенное раскрытие. Под капотом используется NSPanel, но без визуального оформления отдельного окна.

Отсутствие изображений в текущей проверке объяснено пользователем: macOS не предоставила Screen Recording. Скрытие, hover и локальные меню работают без этого доступа; точные снимки status icons текущим способом недоступны. В режиме без захвата отображаются подписи, app icons не подставляются, автоматического запроса Screen Recording нет. Полная визуальная проверка новой формы пока не выполнена.

Актуальное поведение бабла: физический/виртуальный вырез в строке меню сохраняет свой размер. Раскрытие и сворачивание целиком происходят ниже него с зазором 6 pt; окно не расширяет чёрную область внутри строки меню. Вертикальные отступы компактного бабла суммарно 20 pt вместо прежних 36 pt; размер кнопок сохранён. Размер округлого бабла зависит от числа кнопок: один ряд до шести значков, дальше сбалансированные центрированные ряды, до трёх видимых рядов со скроллом. Короткие ряды центрируются независимо. Системное окно остаётся borderless, без titlebar и служебных команд.

Последнее уточнение формы: шторка и бабл образуют один непрерывный чёрный контур. Зазора между ними нет. В верхней полосе контур ограничен шириной реального/виртуального выреза, а ниже плавные плечи переходят в адаптивную область значков. При раскрытии нижняя область растёт по высоте и ширине, сохраняя соединение с верхней частью. Это заменяет предыдущий отделённый бабл с зазором 6 pt. Тесты проверяют непрерывность центральной линии и отсутствие расширения контура в строке меню; реальная визуальная проверка анимации остаётся открытой.


Текущий способ значков без экрана заменяет все прежние инструкции о Screen Recording и снимках. Флаг `menuBarSnapshotsEnabled` в старых настройках игнорируется и исчезает при следующем сохранении; выбранные приложения сохраняются. 54 unit-теста прошли, включая загрузку именно StatusIcon, отказ от Dock fallback и миграцию. Ресурс установленного Telegram отдельно проверен: 16×16 pt, непустая alpha-маска, executable bundle не загружается. Полный интерфейс новой установленной копии вручную пока не проверен.


Расширение ресурсных значков без экрана: добавлены Vorssaint (`MenuBarIcon`, 26×20 pt), AWDL Control (`MenuIcon`, 20×20), BetterDisplay (`BetterDisplayStatus`, 16×16), Docker (`statusItemIcon-0`, 29×22), Cursor (macOS `tray/darwin/trayTemplate.png`, 16×16). Все ресурсы успешно загружены отдельной пробой из установленных приложений; Dock icons не используются. Для Red Shield VPN и OpenVPN Connect подходящий отдельный ресурс пока не найден, остаются подписи. Это статические рисунки, без синхронизации connection/activity/badge-состояний. 56 unit-тестов прошли, включая ресурсные layouts новых владельцев и отсутствие fallback для VPN.
